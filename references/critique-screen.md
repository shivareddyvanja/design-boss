# Single-Screen Critique

Use for a rendered screen or screenshot; judge visible evidence and separate unverified behavior from observed issues. For an app or flow, also use [multi-screen critique](critique-system.md).

Review in order:

1. **Task and hierarchy:** identify purpose, state, focal point, and next action; check reading path and competing emphasis.
2. **Composition:** examine grouping, spacing, alignment, density, surfaces, and relationships to the user's task. On frequently used screens, check whether headings or decoration delay access to the primary content or action; consider a more compact treatment when it improves repeated use.
3. **Visual craft:** inspect typography, wrapping, contrast, icon consistency, imagery, surface depth, and whether the result has a product-specific thesis.
4. **Interaction and accessibility:** check visible affordances, relevant states, safe areas, targets, text scaling, and whether meaning depends on color or motion. Trace actual behavior using [product integrity](product-integrity.md) when evidence exists.
5. **Production plausibility:** check realistic content, component reuse, feasible effects, and the selected platform.

Check rendered labels and variable content for correct spacing, pluralization, currency/date/unit formatting, and wrapping in the target locale when relevant. Prefer the project's formatting and localization tests; visual inspection alone cannot validate every data or locale case.

For each important finding, state priority, visible evidence, user impact, and a concrete change. Do not imply a state or action was tested when it was not. For critique-only work, report recommendations without editing.

## Template signals

Investigate generic unrelated statistics, repeated cards without grouping value, oversized decorative content hiding the task, effects without a product purpose, uniform emphasis, placeholder content, and ambiguous persistent actions. These are signals, not bans. For substantial visual work, two or more distinct unexplained signals require a meaningful revision and a fresh visual review; justified patterns are not failures. When review or revision is unavailable, report the limitation.

Use [redesign review](redesign-review.md) to compare outcomes and catch regressions. Use the [visual critique index](visual-critique.md) for an optional detailed scorecard.
