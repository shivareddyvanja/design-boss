# Composition and Surface Decisions

Use when hierarchy, grouping, density, or repeated containers are the issue. For responsive details and stress cases use [composition](composition.md).

- Define each screen's main job and reading path: orientation, current information, next action, supporting content, and recovery as relevant. Choose an appropriate focal model: task, status, content, decision, or progress.
- Establish visual relationships using alignment, scale, whitespace, type, dividers, imagery, and surface treatments. Tight spacing groups; larger spacing separates. Avoid giving every block identical emphasis.
- Let density reflect expertise, frequency, content, and risk. Dense tools can be compact if scannable; avoid shrinking text to compensate for unresolved hierarchy.
- On frequently used screens, consider how much space headings and decorative elements take from the content or actions people return for. Use a more compact treatment when it makes repeated use easier while preserving the product's character.
- Give a major surface a concrete job: interaction boundary, selection/state, semantic grouping, layering/scroll, or meaningful contrast. If it has no such purpose, compare a version without it. Reuse established components when appropriate; cards and nested surfaces are not prohibited.
- Put a primary action where it follows the relevant content or decision. Sticky controls must leave content, keyboard, and system regions accessible. Peer choices may deserve equal emphasis.
- When a requested redesign targets repetitive composition, test structurally different alternatives using [redesign review](redesign-review.md) and compare actual renders rather than just changing colors or labels.
